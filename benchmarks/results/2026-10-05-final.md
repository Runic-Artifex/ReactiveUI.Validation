These are **provisional shared-host observations**. Independent DynamicData work
and other tasks were running on this machine. High-priority scheduling was
unavailable, and several confidence intervals are wide. The samples do not
establish which flavor is faster, identify the cause of allocation differences,
or demonstrate improvement over the historical timings. Repeat focused runs on
an idle host before drawing comparative conclusions.

Each invocation performs two changes and restores its initial state. Context
updates change one controlled component's message twice while all ten components
remain invalid, including state/text creation. Property updates notify ten rules
on one property and the active aggregate. Binding replacement switches one plain
CLR view from its first model to its second and back; each existing model owns
ten property rules. Model/rule construction is outside binding timing. Binding
assignment includes a small counter used to catch transient stale writes in
setup. Allocation units are BenchmarkDotNet KB (**1024 bytes**), managed only.
These workloads measure synchronous library throughput, not UI dispatcher,
rendering, bridge, asynchronous model-turn, or end-to-end latency.
