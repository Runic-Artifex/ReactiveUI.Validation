# Historical normal API peer

The two frozen assemblies were compiled before the new capability packages against the accepted CI shipping pair from source `2550376b230ccfb78beb8d3b4ced8866b65d809e`, Validation `8.1.0-runic.0.790.17.15.10` and DynamicData `10.0.0-runic.5`. `provenance.json` records the exact archive, reference, analyzer, source, project, compiler input, graph, log and PE hashes. Each original PE contains both a normal `ValidationRule` call and its method-group `ldftn`; neither references the new capability namespace.

The projects exclude only the historical Validation analyzer so it cannot replace those original calls with generated interceptors. The other packaged analyzers remain enabled. The peer source has no new runtime-dispatch attribute or registration API. Final acceptance links these unchanged PEs into the new managed, full-trim and native application and supplies an explicit finite scoped catalog from that application. Compilation and IL inspection alone do not establish runtime compatibility.

To reproduce the historical compilation, use the locked `runic-sdk` shell and a separate NuGet configuration/cache containing exactly the four archive hashes recorded in `provenance.json`, plus NuGet.org for their published dependencies. Build each project in Release with warnings treated as errors. Preserve its captured `obj/generated-compiler-input.txt`, original compiler source snapshots and `project.assets.json`; inspect the PE with `GeneratedSourceInspector legacy-pe`. Reproduction outputs must be compared with the frozen provenance and must not silently replace the accepted binaries. The ordinary final gate verifies the retained bytes and never recompiles these peers against the new library.
